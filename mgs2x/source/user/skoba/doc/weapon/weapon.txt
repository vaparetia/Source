○ai_ray_layoutの仕組み
説明
	アーセナルで登場するデモ用RAY主観です。
	スティンガーのプログラムから派生しているので、内容はスティンガーと
	同じです。不必用な部分は外されています。
	メッセージを受け取ると、バグ演出を実行します。

○arms_conの仕組み
説明
	デモ用マズルフラッシュ等のエフェクトマネージャです。
	メッセージで区別してどのエフェクトを呼ぶのかを決定しています。

○clay_effの仕組み
説明
	クレイモア火線エフェクトです。
	最初にランダムで火線の長さをきめ初期化をします。
	その後その領域をしようしてストリップで線を描いています。
	αが０になるまで処理は続きます。

○clay_mngの仕組み
説明
	クレイモアマネージャです。
	ここから、クレイモアのエフェクトを全て呼びます。
	振動の管理も行っています。

○demo_dg_cam_layoutの仕組み
説明
	デモ用にアレンジされたPLANT編デジタルカメラレイアウトです。
	親からのシグナルにより、表示/非表示を切替える事が可能です。

○demo_dg_cam_shuter_layoutの仕組み
説明
	ただレイアウトを再生して終了するプログラムです。

○equip_layoutの仕組み
説明
	ただレイアウトを再生してするだけです。
	メッセージにて表示/非表示を切り換える事は可能です。

○night_layoutの仕組み
説明
	ただレイアウトを再生してするだけです。
	後はメーター等を計算して動かしているだけです。

○nikita_layoutの仕組み
説明
	ただレイアウトを再生してするだけです。
	真中の数値はランダムです。
    Lockon属性のTargetをもっている物体にのみENEMYと表示するようになっています。

○psg_layoutの仕組み
説明
	ただレイアウトを再生してするだけです。
	真中のラインを角速度で動かしています。

○ray_layoutの仕組み
説明
	ただレイアウトを再生してするだけです。
	ロックオン機能があるように思いますが、これは機能していないので注意してください。
	その他は、ほぼスティンガーと同じ作りです。

○scope_layoutの仕組み
説明
	ただレイアウトを再生してするだけです。
	グラフの動きに規則性はありません。

○stg_layoutの仕組み
説明
	ただレイアウトを再生してするだけです。
	Target属性をみてロックオンしてもよいのかを判定します。
	良かった場合、マップ内にいるのか？ENEMY_SIDEなのか？対象が画面内にいるのかをチェックします。
	対象がロックオンしても良いものであった場合はZ値をキープしておきます。
	最終敵にプレイヤに一番近い対象をキープされていたなかから選びロックします。

○tdg_cam_layoutの仕組み
説明
	ただレイアウトを再生してするだけです。
	パッド操作はサムネイルを表示している部分の枠が動いている場合は受け付けないようになっています。 

	サムネイルの動きについて
		現在撮影した場所から次のブランクに移る時の条件は以下の通りです。
		現在撮影した場所以外にまだ撮影をしていないブランク領域があるかどうか。
		無い場合はその場に留まります。

○thermal_layoutの仕組み
説明
	ナイトビジョンと同じです。
	ただレイアウトを再生してするだけです。
	後はメーター等を計算して動かしているだけです。

○vtr_layoutの仕組み
説明
	デモのみ使用。
	ただレイアウトを再生してするだけです。

○stgの仕組み
説明
	スティンガーのモデル、レイアウトの起動、表示／非表示を
	制御しています。

○usp.c
	・プレイヤーのUSP、SOCOM、M4、Aksの共通プログラム。
	・プレイヤーから引数で、トリガー変数のポインタをもらい、
	  それに従って処理が行われる。
	・マガジン、薬莢、マズルのプログラムはここからコールされる。
	・レーザーサイト処理は、TARGET_SEEKクラスのオンラインターゲットとオンラインハザード
   	  チェックで作ってある。

○blade.c
	・プレイヤーのブレードのプログラム。
	・プレイヤーから引数で、トリガー変数のポインタをもらい、
	  それに従って処理が行われる。
	・装備刀と抜刀時／納刀時の刀は別キャラになっている。
	・峰討ち刀モデルも同時に生成されており、表示／非表示で制御している。
	・ダメージ値、攻撃範囲は外部から関数で変更できるようにしてある。
	
○grenade.c
	・プレイヤーのGrenade,Chaff,Stun,Magazineの共通プログラム。
	・プレイヤーから引数で、トリガー変数のポインタをもらい、
	  それに従って処理が行われる。
	・ピン、レバーのモデルも生成している。
	  ピン抜き時にピンが飛び、投擲時にレバーが飛ぶ。
	  ただしイントルード中はピンは飛ばない。
	・投擲時に、プレイヤー腰と手の位置の間に壁があるときは、
	  グレネードは腰の位置から出るようにしてある。	
	・ピンを抜いた後で、強制モードやデモに入ったら、
	  ピンを抜く前の状態に戻している。	
	・ピンを抜いて5秒投げないでいると持ったまま爆発する。
	  このときはチャフやスタンでもダメージを受ける。

○spray.c
	・プレイヤーのスプレー、マイク共通プログラム。
	・プレイヤーから引数で、トリガー変数のポインタをもらい、
	  それに従って処理が行われる。
	・マイクは上下左右に振ったときのサウンド、ＳＥ制御もしている。

○book.c
	・プレイヤーの雑誌プログラム。
	・プレイヤーから引数で、トリガー変数のポインタをもらい、
	  それに従って処理が行われる。
	・地面に置くときに本を開く。開いている最中にキャンセルされる（ダメージなど）と
	  閉じる。

○cfr.c
	・プレイヤーのＣ4、クレイモア共通プログラム。
	・プレイヤーから引数で、トリガー変数のポインタをもらい、
	  それに従って処理が行われる。
	・クレイモアは、設置準備時に、攻撃範囲イメージ線を表示。
	・設置時のプレイヤーのモーションの手の位置が壁とずれている場合を考慮して、
	  設置時に壁床との距離を見て、ちゃんと接するように調整している。

○nkt.c
	・プレイヤーのニキータ、ＲＧＢ６共通プログラム。
	・プレイヤーから引数で、トリガー変数のポインタをもらい、
	  それに従って処理が行われる。
	・ＲＧＢ６は取っ手つきマガジン、取っ手無しマガジンのモデルも生成し、
	  リロード時に表示／非表示を制御して上手くみせている。
	  主観も客観も同じモデルを使うので、ワールド参照先を毎フレームチェックしている。
	・リロードはＲＧＢ６本体にモーションを付けてやっている。
	  ダメージなどでモーションをキャンセルするのに、TRIG_FALL（グレネード落し命令）を
	  使っている。

○psg.c
	・プレイヤーのＰＳＧ−１、ＰＳＧ１−Ｔプログラム。
	・プレイヤーから引数で、トリガー変数のポインタをもらい、
	  それに従って処理が行われる。
	・ズームカメラ、ぼかしキャラを起動している。

○wp_mng.c
	・プレイヤーの武器モデル管理プログラム。
	・主に、プレイヤー状態による、表示／非表示を制御している。
	・発射武器変数(GM_WeaponFire)の更新処理も行っている。
